# Gameplay systems

> Imported by `../CLAUDE.md` via `@docs/systems.md`. Part of the project guidance — keep in sync with the code.

## Input & focus

Letter keys (especially W/A/S/D/X/C/F/B/V and Space) used to allow browser default actions, which on some setups (notably Windows 11 / Chinese IME, certain Chrome focus modes) would scroll the page even with `overflow:hidden` set on `<body>`. The skill HUD lives near the bottom of the canvas, so any scroll pushed it out of view and the player thought the game was frozen. The current input layer defends against this in four places:

1. **`GAMEPLAY_KEYS` Set** — every key the game listens for is in this set, and the global keydown/keyup handlers `preventDefault()` for anything in it.
2. **Canvas is focusable** — `canvas.tabIndex = -1`, `outline:none`, focused on every mousedown and on `window.load`. Keys route through a focused canvas which has no default scroll behavior.
3. **Hard scroll-lock** — a `window.scroll` listener immediately snaps `scrollTo(0, 0)` if anything (browser auto-scroll-into-view, virtual keyboards, extensions) tries to move the document.
4. **`Cmd/Ctrl + scroll` is not touched** — only key-driven scrolling is suppressed.

When adding a new gameplay key, **also add it to `GAMEPLAY_KEYS`**, or the bug returns.

## Special skills (X / C / F / B / V) — now a PROFILE LOADOUT

**The fixed per-class skill kit was replaced by a meta-progression LOADOUT** (see the meta-progression bullet in session-changes). The live game no longer reads `CHARACTERS[char].skills`; it reads **`player.loadout`** (built by `resolvePlayerLoadout()` in `createPlayer` from the persistent `profile`):

- **F is locked to HEAL** — the default skill every player owns from the start.
- **X / C / B / V are assignable loadout slots.** A slot is active only if it's **unlocked by level** (`unlockedSlots() = min(4, floor(profile.level/5))`, slot order X→C→B→V — so +1 slot every 5 levels) **AND** assigned in `profile.loadout[slot]` **AND** that skill id is in `profile.ownedSkills`. LMB and the held-RMB secondary stay class-locked (not part of the loadout).
- The `updatePlaying` dispatch loops `[['KeyF','f'],['KeyX','x'],['KeyC','c'],['KeyB','b'],['KeyV','v']]`, firing `triggerSkill(player.loadout[slot], …)` and charging `skillCd[slot] = skillCdFor(id)` on success. Skills you own/equip come from the **`SKILLS`** catalog (id = a real `triggerSkill` case; bought in the shop). `drawSkillHUD` builds its chips from `player.loadout` + `SKILLS` (cooldown bar uses `skillCdFor(id)`).
- **Skills are 5-TIER.** Every `SKILLS[id]` carries a `t:[{cd, …effect knobs}×5]` array; the active tier comes from **`profile.skillLevels[id]`** (1..5, default 1 when owned). Helpers: `skillTier(id)` / `skillStat(id)` (active tier's knobs) / `skillCdFor(id)` (active tier's cd, with a fallback to the vestigial `player.skillCdMax` map then `t[0].cd`) / `skillUpgradeCost(id)` (`cost*SKILL_UP_MUL[nextTier]`, free skills use `SKILL_UP_BASE_MIN`) / `skillBlurb(id,tier)` (short effect string for the HUD/shop). `triggerSkill(name,…)` reads `skillStat(name)` for every magnitude/duration, so a higher tier is automatically stronger (effects grow, cd shrinks; tier ~3 ≈ the old single value). Sprint's % is stashed in `player.sprintMult`, napalm's damage mult in `player.flameburstMul` (set per-cast, read by `playerSpeedMult`/`tickFlameburst`). Upgrade tiers in the SHOP skills tab (compact grid + 5 pips + hover detail panel). `triggerSkill` returns `true` on a successful fire so a slot only charges its cooldown on success.
- **`resummon`** is a universal loadout skill (revives a DEAD equipped assistant near the player; returns false — no cooldown — when none are dead; higher tiers grant the revived ally brief invuln + can revive 2). It uses an existing X/C/B/V slot, so **no new GAMEPLAY_KEYS entry**.
- **`CHARACTERS.skills`/`skillLabels` are now vestigial** — kept only so `validate.py` C7 stays green; they no longer drive gameplay. `player.skillCdMax` (looked up by skill name) is likewise only a `skillCdFor` fallback now — the live per-tier cooldowns live in `SKILLS[id].t[…].cd`.

- **X is `sprint`** (label `SPRINT`, 20 s cooldown): sets `player.sprintTime = 5`, a +30% move-speed buff. `playerSpeedMult()` combines it with the SPEED powerup (1.5×) multiplicatively, and is used by both player movement and the allies that pace themselves to the player. Shows a `SPRNT` buff timer in `drawWeaponHUD`.
- **C is class-specific**: Soldier `flameburst` (label `NAPALM` — 3 s fire ring via `tickFlameburst`, 20 s cd), Scout `blink` (teleport to cursor, 0.45 s i-frames, 7 s cd), Tank `wall` (4 s full invuln, 18 s cd).
- **F is `heal`** (label `HEAL`, 20 s cooldown): restores 1 HP capped at `maxHp`. Returns `false` (and so charges no cooldown) when already at full HP, so it never wastes the cooldown.
- **B is `blast`** (label `BLAST`, 20 s cooldown): a **circle-damage** AoE burst (radius 70) centered on the player via the shared `explode()` primitive — every enemy inside the radius instantly takes normal damage (`3 × damageMult`, doubled by the DAMAGE powerup). It also spawns an expanding cyan **shockwave ring** particle (`{ring:true, r0, r1}`, rendered as a growing `ctx.arc` stroke in the particle draw loop) so the circular area of effect is visible.
- **V is class-specific**: Soldier `barrage` (label `BARRAGE` — fan of 5 staggered grenade-shells, 24 s cd), Scout `dash` (directional dodge w/ 0.35 s i-frames, 5 s cd), Tank `vsummon` (label `BLADE+`, 25 s cd — the one-alive-at-a-time sword knight, `attackRate /= 1.5`; the only way to summon a `sword_ally`).

`drawSkillHUD()` pushes chips in order X, C, F, B, then V (V only when `ch.skills.v` exists — now always true). Chip colors come from the `skillColor` map (which includes `barrage`, `dash`, `blink`, `flameburst`). The character-select card lists the same slots, laid out sequentially (`sy` accumulator) so optional rows never overlap; the card is 172 px tall and fits five skills for every class (Soldier/Scout have only 3 stat rows — HP/SPEED/DMG, no SHIELD/FUEL — so they have *more* slack than the tank card). Each key's `updatePlaying` dispatch is gated on its `charSkills.<k>` entry, so adding/removing a slot on a class is purely a data change in `CHARACTERS`.

The old M-slot was removed. Of the spare `triggerSkill` handlers, `dash`/`blink`/`flameburst` are now **wired** (Scout V / Scout C / Soldier C). `grenade`, `nuke`, and `summon` remain implemented but **unreferenced** (`grenade` was briefly Soldier's RMB before it became the knife slash — its bullet *shape* is still mirrored inline by the `barrage` V handler; `summon` was X's old sword-summon, superseded by `vsummon`); leave them for future characters.

## Right-mouse secondaries (RMB)

Each class has a distinct held-RMB secondary attack, dispatched per-frame in `updatePlaying` right after the movement/shoot block (next to each other, mirroring structure):
- **Benjamin Wu (Tank)** — `fireFlamethrower(dt)` while `fuel > 0` (drains `player.fuel`). A **close-quarters** cone: `range 140`, `halfAngle 0.52` (~60° cone) — a deliberately SHORT, tighter scope. Damage is **distance-scaled** (the flame is hottest at the nozzle): a per-enemy `distMult` lerps from `DIST_NEAR 1.9` at point-blank down to `DIST_FAR 0.4` at the edge of `range`, so the base `dps 7` (×`damageMult`, ×2 with the DAMAGE powerup) lands ~13 DPS up close and ~3 DPS at the fringe — rewarding the high-HP tank for face-tanking. The visual flame-particle spray reads from the same local `range`/`halfAngle`, so it shrinks in lock-step. Plays a **firewood-burning** crackle (`sfx.flame` — a quiet low ember bed + frequent random sharp crackle-pops) at ~10 bursts/sec via a `player.flameSfxT` cadence (the fn runs every frame while held, so it can't fire the sound un-throttled); the per-pop randomness makes it sound like uneven burning wood rather than a steady jet.
- **Syed (Soldier)** — continuous **blade slash** via `fireKatana(dt)` (function/const names `fireKatana`/`KATANA_*` are legacy — the sprite is now a rainforest warrior with a dagger, not a katana): a VERY-high-DPS melee swept over a wide **obtuse** arc (`KATANA_RANGE 32`, `KATANA_HALF 0.9` rad ⇒ ~103° total — still obtuse, 3/4 of the original 137° after a scope cut, `dps 40 × damageMult`). It drains `player.energy` (a ~6 s pool, like Tank's fuel) while RMB is held and `energy > 0`. `drawPlayer` renders the obtuse arc as a faint steel sector **plus a fast sweeping blade slice** — a crescent edge + radial blade line whose angle oscillates **very rapidly** across the arc (`p.angle + sin(stateTime*75)*KATANA_HALF`), so it reads as a knife being swung at high speed rather than a static cone (still using the same `KATANA_RANGE`/`KATANA_HALF` consts, so the visual and the damage check stay in lock-step). Plays a sharp **knife-whisk** swish (`sfx.slash`) at ~10 swishes/sec (a rapidly-swung knife) via a `player.slashSfxT` cadence (the fn runs every frame while held). Refilled by the **`beverage`** pickup (+1 s each, Soldier-only) and a slow 0.1/s self-regen (below).
- **Scout** — THREE straight-line **hitscan laser beams** via `fireLaserBeams()` (no longer travelling projectiles): on each release the mech fires three straight beams fanned around the aim (`±LASER_BEAM_SPREAD 0.18` rad + one dead-center). Each beam is a line segment from the muzzle out to `LASER_BEAM_LEN 147` (= the old bolt's `speed 420 × life 0.35`, so the **scope is unchanged**). It is HITSCAN — a point-to-segment distance test damages **every enemy whose center lies within `LASER_BEAM_HALF 4` + its radius of the beam line simultaneously**, the same frame the beam fires (`dmg 3 × damageMult`). Gated behind a `player.laserCd` **0.22 s** cooldown (cadence) **and `player.power`** — a ~20-volley resource pool (`maxPower 20`, Scout-only) that costs **1 per volley**; when `power < 1` the beams stop until it regens/refills. Rendered as three fading straight lines (a `{beam:true, x, y, angle, len}` particle drawn as a translucent wide glow + bright thin core in the particle loop) — this is how the "three lines" are manifested in-game. Blue muzzle particles + blue barrel reticle while RMB held. Plays a **laser-firing** "pew" (`sfx.laserBeam`, a diving sawtooth + zap fizz) once per volley — already cadence-gated by the `laserCd`, so no extra throttle is needed. (The old `SPR.bullet_laser_blue` sprite is now orphaned.) **The Scout's LMB primary** now fires **light dots of blue laser light** — a small, pale 3×3 `SPR.bullet_dot_blue` speck (near-white core) with light-blue (`#b3e5fc`) muzzle particles, kept deliberately airy/lightweight (its sound stays `sfx.shoot`).

`laserCd` is decayed alongside the weapon timers; the three RMB resources are drained inside their own RMB blocks — Syed `energy` and Benjamin Wu `fuel` by `dt` while held, Xu Yihui `power` by 1 per laser volley — and all **slowly self-regen in `updatePlaying`** just before the RMB blocks: **Syed `energy` 0.2/s**, **Benjamin Wu `fuel` 0.1/s**, **Xu Yihui `power` 0.6/s**. None is fully dependent on its `beverage`/`fuel`/`battery` drop (each weight 0.12). **All three pools regen ALWAYS now, even while RMB is held** (the `!mouse.rdown` guard that used to gate `power` was removed, so the Scout matches the other two). **Pay-per-use gate:** the secondary fires only when the pool can fully pay for the use this frame — Syed `energy` / Benjamin Wu `fuel` need `>= dt`, Xu Yihui `power` needs `>= 1` (one volley). When the pool is too low the RMB block simply doesn't run, so the secondary deals **ZERO damage** while insufficient — and the `>= cost` gate (vs the old `> 0`) means there's no leftover partial-frame tick at the moment it empties. **ALL THREE classes now share a fixed 1 s no-fire lockout (`player.rmbLockT`) the instant the pool empties:** the RMB block sets `rmbLockT = 1` when the post-drain pool can no longer pay for a use (energy/fuel fall below `dt`; power falls below 1 after a volley), and every RMB block is gated on `rmbLockT <= 0`, so the secondary can't fire for a full second after running out. **The lockout — not a regen pause — is what prevents near-empty stutter-fire** (a continuously-drained pool can't fire for 1 s, then only resumes once recovery has put real charge back; before the lockout existed, the trickle re-crossed the cost threshold every few frames and sputtered free damage with the bar empty). Because the pools regen while held, they **recover during the lockout**, so holding RMB on an empty pool yields a short burst roughly once per second (recover a little → fire briefly → re-lock) rather than nothing. **The Scout's `power` was previously the exception** (released-only regen + no lockout, to stop it trickle-firing volleys); it now regens while held + locks out like the others, so the behaviour is uniform across all three classes. (An earlier 30%-recharge lockout with a `rmbLocked` flag was tried and removed; this is a simpler fixed-1 s timer, not that flag.) `drawPlayer` has per-class RMB reticle-color branches so the barrel lights while RMB is held. **HUD:** Syed's energy shows as a label-only **ENERGY** bar in `drawHUD`, Benjamin Wu's as a **FUEL** bar, Xu Yihui's as a cyan **POWER** bar — bar fill only, no numeric value; only one of `maxFuel`/`maxEnergy`/`maxPower` is ever >0 so the three bars share the same screen slot.

## Pause (Space)

A global `let paused = false;` (declared next to `slowMoTime`). During `STATE.PLAYING`, the **leading edge** of a Space keydown toggles `paused` (the keydown listener checks `!wasDown` to ignore key-repeat). While paused, `update()` skips `updatePlaying(dt)` so the whole tick freezes (timers, spawns, movement, skills). `draw()` still renders the frozen world + HUD and overlays `drawPause()` (dim + "PAUSED" banner). **Resume** is either another Space press or a click anywhere: the canvas `mousedown` handler returns early when `paused` so the resuming click doesn't also fire a shot. `paused` is reset to `false` in `startGame()` and `startLevel()` so it never persists across transitions.

## Character stats window (Tab)

A global `let showStats = false;` (declared next to `paused`). During `STATE.PLAYING`, the **leading edge** of a **Tab** keydown toggles it (the keydown listener checks `!wasDown`). **Tab is in `GAMEPLAY_KEYS`** so its `preventDefault` stops the browser's focus-traversal (Tab would otherwise move focus off the canvas). While the window is open `update()` skips `updatePlaying(dt)` (the gate is `if(!paused && !showStats)`), so it **freezes the tick exactly like pause** — the listed values can't change while you read them, and it's safe to inspect mid-fight. `draw()` overlays `drawStats()` (its `else if` is checked **before** the pause branch). **Close** it with Tab again, with a click anywhere (the `mousedown` handler returns early when `showStats`, so the click doesn't fire a shot — mirrors pause), or with **Escape** (which closes the window *instead of* quitting to menu when it's open — see below). `showStats` is reset to `false` in `startGame()`/`startLevel()` and on the Escape-to-menu path.

`drawStats()` is a screen-space, dim-backed two-column panel that reads the player's **live, level-scaled** basic parameters straight from the same data gameplay uses (so it can't drift): **DEFENCE** (HP, shield, HP-regen — now the equipped **HP REGEN passive** value or `—`), **MOBILITY** (base move speed, with the effective speed in parens when a SPEED/SPRINT/**SWIFTNESS** buff is up), **PRIMARY ATTACK (LMB)** (per-class weapon name + `dmg/hit` = base×`damageMult` + shots/s from the cadence — note the Scout LMB cadence is the fixed `0.06`, not `fireRate`), **SECONDARY ATTACK (RMB)** (weapon, damage as DPS for Syed-blade/Benjamin-flame or per-beam for Xu's lasers, the FUEL/ENERGY/POWER pool capacity, its per-second regen, and a cadence/note line), **GENERAL** (overall `damageMult`, the equipped **LIFESTEAL passive** value or `—`, account LV), and a full-width **EQUIPPED PASSIVES (n/max)** line listing every equipped passive's live value. HP-regen + lifesteal are now **universal equippable passives** (read via `passiveValue`), no longer class-locked. When you add/rename a class attack, RMB pool, or regen rate, **also update the matching per-class branch in `drawStats`** so the window stays truthful. `headless_check.py` exercises `drawStats` for all three classes as a draw-time smoke check.

### Menu version: the CHARACTER PARAMETERS screen (`STATE.PARAMETERS`)

The same information is also reachable from the **initial interface** without starting a run: a **`PARAMETERS`** button in `drawMenu` (top-right, just below the profile bar's COINS line — `parametersButtonRect()`) opens `STATE.PARAMETERS` (`drawParameters`/`handleParameters`). Because there's no live `player` on the menu, values are computed by the pure helper **`scaledStatsFor(charKey, level)`** (a mirror of `applyLevelScaling`/`createPlayer`: base LMB cd `0.14`, base RMB pools `12`/`6`/`20`). The screen has three **class tabs** (`paramChar`, `paramTabRect(i)`) and, unlike the Tab window, shows **the per-level GROWTH** of each stat: every numeric row has a `(+x)` token computed as `scaledStatsFor(c, lvl+1) − scaledStatsFor(c, lvl)` (the `lvl+1` is clamped to `LEVEL_CAP`, so the tokens read `(+0)` at max level; non-scaling stats like move speed / shield / regen / lifesteal / **RANGE** are always `(+0)`). It also manifests the game's **distance unit**: MOVE SPEED is shown in `px/s`, both attacks list a **RANGE** row in px (LMB reach = projectile speed×life — scout 360 / tank 480 / soldier 432; RMB reach + scope — soldier `32 px · ~103° arc`, scout `147 px · 3 beams`, tank `140 px · ~60° cone`), and a one-line distance legend (`px = game pixels …`). Below the columns it also shows an account-wide **EQUIPPED PASSIVES (n/max)** block listing all 8 universal passives with their live value (or `—` when not equipped) — the HP-REGEN / LIFESTEAL rows are likewise passive-driven now, not class-locked. `draw()` skips `drawProfileBar` on this state (it prints ACCOUNT LV itself), and `< BACK` (or Escape) returns to the menu. Keep `scaledStatsFor` in lock-step with `applyLevelScaling` and the per-class base-attack constants if either changes.

## Quit to menu (Escape)

The keydown listener also handles **Escape** (leading edge): from **any state except `MENU`** it sets `state = STATE.MENU; stateTime = 0; paused = false; showStats = false;` — abandoning the current run / setup screen and returning to the "initial interface". **Exception:** if the stats window is open during play (`STATE.PLAYING && showStats`), Escape just closes the window and stays in the run. No entity cleanup is needed because the next run resets `entities`/`particles` in `startSelectedRun`/`startLevel`. Escape is **intentionally NOT in `GAMEPLAY_KEYS`** (no `preventDefault`): it doesn't scroll the page, and suppressing it would block the browser's fullscreen-exit. Mirrors the existing LEAVE-to-menu paths in `handleLevelComplete`/`handleEndScreen`.
