# Session changes (recent design decisions)

> Imported by `../CLAUDE.md` via `@docs/session-changes.md`. Part of the project guidance — keep in sync with the code.

These changes are recent enough to be worth recording so future passes don't unintentionally regress them:

- **Shop skill prices raised, profile `LV` right-aligned, loadout slots now HOVER-to-pick (dropdown) instead of click-to-cycle.** Three small follow-up tweaks (all in `index.html`):
    - **Skill costs ~doubled** in the `SKILLS` catalog (skills are a bigger gold sink than an assistant upgrade level): tier-1 ~280-400, tier-2 ~680-820, tier-3 ~1150-1450, `nuke` 2000 (was 120-180 / 300-360 / 520-640 / 900). Only the `cost` fields changed — `cd`/tiers/labels untouched, so validator C7 + headless are unaffected.
    - **Profile bar `LV n` moved from left- to right-aligned** (`drawProfileBar`): both `LV n` and `COINS: <n>` now hug the bar's right edge, with the XP bar between them. (The bar itself stays in the top-right corner.)
    - **Loadout skill slots are now a hover dropdown.** Hovering an unlocked X/C/B/V slot on the LOADOUT screen opens a click-to-choose list (`— EMPTY —` + each owned non-heal skill) instead of cycling on click. New module state `loadoutMenuSlot` (slotKeys index 1..4, -1 = none) + geometry helper `loadoutMenuRects(i)` (list anchored under the slot, shifted up to stay on the 270px screen). `handleAssistantSelect` runs hover detection **every frame** (before the `mouse.clicked` guard): an already-open menu wins (no flicker), else the slot under the cursor opens, else it closes; a click on a list entry assigns it (with the same no-duplicate-across-keys rule) and closes the menu. `drawAssistantSelect` renders the panel on top, after BACK. Reset to -1 on entering the screen / BACK / START. The old click-to-cycle block was removed; the hint changed `TAP TO CYCLE` → `HOVER A SLOT TO PICK`.
- **Per-assistant 10-level upgrade system + assistants weakened at low level + non-game UI layout move.** Three coupled changes (all in `index.html`):
    - **Assistant leveling (1..10), upgraded with gold in the SHOP.** New `profile.assistantLevels` map (`{ drone:1 }` default; sanitized in `loadProfile` to 1..10 for every owned ally). TUNABLE consts in the profile block: `ASSIST_MAX_LEVEL=10`, `ASSIST_UPGRADE_BASE=50`, `ASSIST_UPGRADE_GROWTH=1.4`. Helpers `assistantLevel(key)`, `assistLevelFrac(lvl)` (**0.35 at L1 → 1.0 at L10**), `assistUpgradeCost(lvl)=round(50*1.4^(lvl-1))` (~50→738 per level; ~2457 total L1→L10). **`createAssistant` now builds the base factory entity then calls `applyAssistantLevel(a,key)`**, which treats the factory stats as the **L10 reference** and scales HP / damage / range / attack-speed down by `assistLevelFrac` (range & rate scale gentler than raw power). So a fresh (L1) ally is at ~35% power — that is the "significantly reduced" base; each upgrade buys it back toward full. The drone's bullet `dmg`/`detectRange` were moved out of `updateCompanion`'s hardcoded literals into `createCompanion` fields so they can be scaled.
    - **SHOP assistants are now BUY + UPGRADE.** `SHOP_ASSIST_ORDER` gained `drone` (owned by default, but upgradable). Each card shows `LV n / 10` + a level bar; the bottom line is `G <buyCost>` if unowned, `UP  G <upgradeCost>` if owned & not maxed, or `MAX LV`. `handleShop` buys (unlock at L1) when unowned else upgrades +1 level. The LOADOUT (`drawAssistantSelect`) card shows each ally's `LV n / 10` (replaced the vestigial DEFAULT label).
    - **UI layout.** The `? GUIDE` button moved to the **top-LEFT** (`guideButtonRect = {x:8,y:8,...}`); `drawProfileBar` moved flush into the **top-RIGHT corner** and now shows `COINS: <gold>` (the specific number) on its own line **just below the XP bar** (was `G gold` on the same row as `LV`).
    - `validate.py` (C1-C8) + `headless_check.py` (40 levels + 19 assertions) both green.
- **Meta-progression: persistent account profile, leveling/stat-scaling, Gold shop, and a customizable loadout (major foundational update).** Five interlocking systems, all in `index.html`:
    - **Profile (persistence).** One shared account profile in `localStorage` key `shooter_profile` (helpers `DEFAULT_PROFILE`/`loadProfile`/`saveProfile` next to `saveCleared`): `{ level, xp, gold, ownedSkills:['heal'], ownedAssistants:['drone'], loadout:{x,c,b,v}, defaultAssistant, equippedAssistants }`. **Shared across all characters** — XP earned on any class credits the one profile. `loadProfile` MUST guard `if(typeof raw !== 'string') return DEFAULT_PROFILE()` because the headless V8 stub returns a non-string Proxy for `localStorage.getItem` (else `JSON.parse` throws and breaks headless). On load it also sanitizes: forces `heal`/`drone` owned, drops loadout ids not owned, caps equipped assistants to owned ∩ 2.
    - **Leveling.** `xpToNext(level)=round(XP_BASE*XP_GROWTH^(level-1))` (progressive); `grantXp`/`grantGold` (TUNABLE consts grouped in the profile block). Per-kill XP/gold **accrue** on `profile` in `killEnemy` (NOT saved per-kill — avoids thousands of writes), and are **banked + resolved into level-ups** at the level-complete / victory / game-over transitions. `LEVEL_CAP=40`.
    - **Stat scaling** (`applyLevelScaling(p)`, called at the end of `createPlayer`, so it applies at RUN START not mid-run): scales **damage** (`damageMult`), **rate of fire / attack speed** (`fireRate` cooldown + Scout `laserCd` via `p.laserScale`), **max health**, and the **RMB "second basic attack" duration** — its `maxFuel`/`maxEnergy`/`maxPower` pool starts SHORT (`RMB_BASE_FRAC=0.4` of the base 12/6/20) and grows with level (`RMB_DUR_PER`/`RMB_DUR_CAP`). At level 1 the multiplicative bonuses are no-ops (only the RMB shrink applies), so headless balance assertions are unaffected.
    - **Drop-rate scaling.** The `killEnemy` drop **gate** scales with `profile.level` (`DROP_LVL_PER`/`DROP_LVL_CAP`/`DROP_GATE_MAX`); the `kinds`/`weights` pools are untouched so C5 stays green.
    - **Skill model REPLACED with a loadout.** Each class keeps its LMB + held-RMB (class identity), but the active X/C/B/V skills are now a **profile-driven loadout**, not the fixed per-class kit. `SKILLS` catalog (id→{label,color,cd,cost,tier}, id = a real `triggerSkill` case; tiers 1-3 by power; `heal` tier 0 free default) + `SKILL_ORDER`; added `grenade`/`slowmo`/`nuke` to `skillCdMax`. **F is locked to HEAL** (the default everyone owns); **+1 equippable slot per 5 levels** (`unlockedSlots()=min(4,floor(level/5))`, slot order X→C→B→V). `resolvePlayerLoadout()` (triple gate: unlocked-by-level AND assigned AND owned) sets `player.loadout`; the `updatePlaying` dispatch + `drawSkillHUD` now read `player.loadout` (was `CHARACTERS[char].skills`). **`CHARACTERS.skills`/`skillLabels` are kept as a vestigial validator fixture** so validate.py **C7 stays green with zero validator edits** (it still finds 3 skills/labels blocks over {x,c,f,b,v} with names in `skillCdMax`). The character-select card's skill rows were repurposed to show class LMB/RMB + "SKILLS: LOADOUT".
    - **Shop (`STATE.SHOP`=8, the ARMORY).** Lower-left SHOP button on MENU opens a tabbed shop (SKILLS / ASSISTANTS) via `drawShop`/`handleShop`; tiered gold costs, OWNED/BUY through `clickedRect`, buy deducts gold + pushes to `ownedSkills`/`ownedAssistants` + `saveProfile`; insufficient-gold flash via `shopMsgUntil` (timed off `stateTime`). Assistant costs in `ASSISTANT_COST` (drone free).
    - **Profile bar.** `drawProfileBar()` is called once in `draw()`'s non-game branch so MENU/HOWTO/CHARACTER_SELECT/ASSISTANT_SELECT/SHOP all show it. It is now flush in the **top-RIGHT corner** (`x = W - bw - 8`): `LV n`, an XP bar (**DARK fill = current XP, LIGHT = remaining to next**), and `COINS: <gold>` (the specific number) on its own line **just below the XP bar**. (See the later *UI layout* bullet — the GUIDE button moved to the top-LEFT so the bar can own the right corner.)
    - **Loadout screen + assistant framework.** `ASSISTANT_SELECT` is now a combined LOADOUT screen: owned-only assistant cards (equip **0..2**, default removable — the exactly-2 gate is gone) + a skill strip (F=HEAL locked; X/C/B/V slots LOCKED below their unlock level, else **hover-to-pick from a dropdown** of owned non-heal skills — *superseded the original click-to-cycle, see the UI-tweaks bullet at the top* — no duplicate id across keys). `startSelectedRun` seeds `selectedAssistants = profile.equippedAssistants.slice()`; `spawnSelectedAssistants`/`refreshAssistants` already `.forEach` so 0/1/2 all work. New rects `shopButtonRect`/`shopTabRect`/`shopCardRect`/`loadoutSlotRect`; helpers `ownedAssistantList`/`cycleSkillList`.
    - **Headless.** Driver resets `profile = DEFAULT_PROFILE()` before `startGame`, exercises the SHOP draw state, and a new balance assertion #19 guards the XP curve / level scaling / slot gating / loadout ownership. `validate.py` (C1-C8) + `headless_check.py` (40 levels + 19 assertions) both green. **Tuning levers** are the `TUNABLE` const block in the profile section + the `SKILLS`/`ASSISTANT_COST` costs.
- **Weapon pickups now ENHANCE the basic attack instead of replacing its form.** Per request: powerups can only enhance the class basic attack (Soldier pistol / Scout blue-dot SMG / Tank slug), never change its projectile form. The 6 form-changing weapon pickups (`rocket`/`laser`/`plasma`/`minigun`/`spread`/`homing`) were **removed** as player pickups; the new weapon-pickup set is **4 timed (~8s) enhancers**: `rapid` (½ cooldown — kept), `damage` (×2 — kept), `pierce` (NEW — sets the bullet `pierce` flag so shots punch through), `multi` (NEW — fires a parallel **double shot**, two bullets offset ±3 perpendicular to aim, same projectile). `fireWeapon` was rewritten from the old priority cascade into a single "build the class-default projectile spec, then apply enhancers (pierce flag + multi offsets) + rapid cadence + damage mult" path. New player fields `pierceTime`/`multiTime` (removed `spreadTime`/`laserTime`/`rocketAmmo`/`minigunTime`/`plasmaTime`/`homingTime`); `applyPickup`, all 3 `killEnemy` drop pools (re-balanced to sum 1.0 — C5 green), the boss guaranteed-drop map, `drawPickupEntity` sprMap/glowColors, and `drawHowTo`'s `eq` list were updated to match. New pickup sprites `p_pierce` (purple arrow) + `p_multi` (twin pellets); the old weapon pickup/bullet sprites are now orphaned (`bullet_homing` + the `homing` flag stay — still used by **enemy** AI). **HUD:** the 4 basic-attack enhancer chips (RAPID/PIERCE/MULTI/DMG) moved out of the bottom `drawWeaponHUD` strip into `drawHUD`'s top-left, stacked **above** the RMB resource bar (FUEL/ENERGY/POWER) via a running `hudY` — "the enhancer sits with the weapon it modifies" (per the request that they be above the secondary attack). The bottom strip now only shows movement/utility buffs (SPEED / SPRNT / SLOW / x2 / MAG). `drawPlayer` barrel-tint branches trimmed to rapid/pierce/multi (+ damage red tip). `validate.py` (C1-C8, incl. C5 pool sums) + `headless_check.py` (18 assertions, 40 levels) both green.

To grow/shrink all four arenas together, change the one `MAP_EXPAND` constant. `validate.py` + `headless_check.py` both green.
- **L31-40 end boss no longer overlaps the mid-boss — 15-30s gap with monsters in between.** Previously the mid-boss (50% spawn gate) and the end boss (all-spawned + most-regulars-dead gate) could be on screen simultaneously. Now for `midBoss` levels the end boss is gated on the **mid-boss's death + a `rand(15,30)`s gap**: new globals `midbossRef` (the live mid-boss entity, so its death is detectable via `.dead`), `midbossDefeated`, `bossGapTimer`, `gapSpawnTimer` (all reset in `startLevel`); `spawnBoss` now **returns** the spawned entity so `midbossRef` can capture the mid-boss. In `updatePlaying`'s spawn section: when `midbossRef.dead` first trips, `midbossDefeated=true` and `bossGapTimer=rand(15,30)`; while the gap counts down a trickle of monsters spawns (`pickWeighted(mix)`, capped at `<10` alive non-boss, `entities.length<480`, these **don't** count toward `total` so they never block the win check); the end boss spawns only once `midbossDefeated && bossGapTimer<=0`. L1-30 (no `midBoss`) keep the original "all spawned + aliveRegular ≤ threshold" gate unchanged. The boss HP bar / arrival flash already key off live `isBoss` entities + `boss.kind`, so they show the mid-boss, then nothing during the gap, then the end boss with no extra wiring. **Headless impact:** the Part 1 driver never shoots, so it now kills the mid-boss + zeroes the gap each Phase-B frame so the end boss still arrives (preserving the "End boss spawned in all: YES" coverage); added DRIVER_BALANCE check #8 that drives the real flow and asserts the end boss waits 15-30s after the mid-boss dies AND monsters appear during the gap. `validate.py` (C1-C8) + `headless_check.py` (18 assertions) both green.
- **Boss gas-bomb no longer a 100%-hit instant chip — 0.5 s arming telegraph.** `bossGasBomb` spawns the poison pool *on* the player (`x:player.x, y:player.y`), so it used to deal `damagePlayer(1)` the same frame it appeared — an unavoidable hit at L30 (Nemesis ANNIHILATOR; reused by Reaper L31+ / Phantom L37+). Each pool now carries a `warn:0.5` field: while `warn > 0` the update loop `continue`s (no `life` tick, no damage, no green wisps) and `drawGame` renders it as a **pulsing hollow yellow ring** instead of the green disc, giving ≥0.3 s to step out of the 34-radius zone before it goes live. The damaging window stays the full 3 s (life isn't ticked during the arming delay). Centralized in `bossGasBomb` + the `groundFields` update/draw loops, so it fixes every boss that drops gas. `validate.py` (C1-C8) and `headless_check.py` both green.

- **Dr.Syed innate passive — 2% LIFESTEAL.** Syed (class `soldier`) heals **2% of all damage HE deals to enemies** (originally 5%), capped at `maxHp`, always on (no key, no cooldown). Implemented as a gated helper `soldierLifesteal(dmg)` (`const SOLDIER_LIFESTEAL = 0.02`, defined just above `explode()`) that no-ops unless `player.char === 'soldier'` and `player.hp > 0` (never revives). It is called at **every site where Syed's own attack subtracts enemy HP**: the player-bullet collision (pistol + powerup weapons), `fireKatana` (blade), `tickFlameburst` (NAPALM), and `explode()` (BARRAGE shells / rocket blasts). **Ally damage is intentionally excluded** — drone/bomber bullets share `owner:'player'`, so they're now tagged `fromAlly:true` (new `createBullet` field + the bomber's raw-bullet literal); the bullet-collision lifesteal is gated on `!b.fromAlly`, and `explode()` gained a trailing `fromPlayer` arg so only player-initiated blasts heal (collision passes `!b.fromAlly`; the end-of-fuse grenade detonation passes `b.owner==='player' && !b.fromAlly`; the `blast` skill passes `true`; enemy explosions pass nothing). Because `explode()`/the melee loops call `soldierLifesteal` **per enemy hit**, the total heal stays exactly 2% of total damage dealt. Healing makes `player.hp` fractional — fine, the HP HUD is a bar (`drawHUD`), not pips. Surfaced on the character-select card as a green `PASSIVE: 2% LIFESTEAL` row below Syed's 5 skills, and in his `CHARACTERS.soldier.desc`. Balance lever: the blade's high DPS × 2% is decent sustain but bounded by the short `energy` pool; the pistol's 2% is negligible.
