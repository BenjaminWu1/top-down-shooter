- **RMB secondary: pay-per-use gate, ZERO damage while the pool is insufficient, NO recharge lockout.** The three RMB blocks in `updatePlaying` fire only when the active pool can fully cover the use: Tank `fuel` / Soldier `energy` need `>= dt` (this frame's cost), Scout `power` needs `>= 1` (one volley). When the pool is too low the block doesn't run at all → the secondary deals **no damage** (and the `>= cost` gate vs the old `> 0` means no leftover partial-frame tick at the instant it empties). **There is no lockout/recharge-wait:** the pool regenerates and the attack resumes the moment it can afford a use. This arrived in steps per request: first a 30%-recharge lockout (`RMB_RECHARGE_FRAC` + `player.rmbLocked` + a RECHARGING HUD state) killed the near-empty stutter-fire, then the lockout was **removed** (flag/const/HUD-treatment all gone; the shared FUEL/ENERGY/POWER bar — one parameterized block in `drawHUD` — just shows the fill).     - **Profile (persistence).** One shared account profile in `localStorage` key `shooter_profile` (helpers `DEFAULT_PROFILE`/`loadProfile`/`saveProfile` next to `saveCleared`): `{ level, xp, gold, ownedSkills:['heal'], ownedAssistants:['drone'], loadout:{x,c,b,v}, defaultAssistant, equippedAssistants }`. **Shared across all characters** — XP earned on any class credits the one profile. `loadProfile` MUST guard `if(typeof raw !== 'string') return DEFAULT_PROFILE()` because the headless V8 stub returns a non-string Proxy for `localStorage.getItem` (else `JSON.parse` throws and breaks headless).
