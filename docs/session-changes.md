# Session changes (recent design decisions)

> Imported by `../CLAUDE.md` via `@docs/session-changes.md`. Part of the project guidance — keep in sync with the code.

These changes are recent enough to be worth recording so future passes don't unintentionally regress them:

- **Xu Yihui laser `power` regen 0.1 → 0.3/s (3×).** The Scout's `power` pool now self-refills three times faster, so the 3× laser-beam RMB comes back online much sooner between volleys. Just the one regen line in `updatePlaying` (`+ 0.3 * dt` instead of `0.1 * dt`); comments in `createPlayer`, the regen block, and the POWER-bar HUD were updated to match. (Syed energy stays 0.2/s, Tank fuel stays 0.1/s.)
- **Every class now has an innate passive (one per character).** All always-on, no key/cooldown, surfaced as a green `PASSIVE: …` row at the bottom of each character-select card (7px font so the longest string fits even on the tank, whose 5 stat rows push the row lowest). The three:
    - **Dr.Syed (`soldier`) — 2% LIFESTEAL** (tuned down from the original 5%; just `SOLDIER_LIFESTEAL`, see the bullet below for the full mechanism).
    - **Xu Yihui (`scout`) — 0.5%/s HP REGEN.** One line in `updatePlaying` right after the RMB-resource regen block: `if(player.char === 'scout' && player.hp > 0) player.hp = Math.min(player.maxHp, player.hp + player.maxHp * 0.005 * dt);`. 0.5% of `maxHp` (=9) per second ≈ 0.045 HP/s — a slow out-of-combat trickle, never revives a dead player. Makes `player.hp` fractional, which the HP **bar** renders fine.
    - **Benjamin Wu (`tank`) — +0.5 FUEL per kill.** Added in `killEnemy`, immediately after the idempotency guard (`en._killed`) so it credits **exactly once per kill** even when a blast + a direct hit both call `killEnemy` on the same enemy: `if(player.char === 'tank' && player.maxFuel > 0) player.fuel = Math.min(player.maxFuel, player.fuel + 0.5);`. Lets the flamethrower sustain itself off kills on top of the 0.1/s regen + fuel pickups. (`maxFuel` is 0 for the other classes, so the `Math.min` would no-op anyway — the explicit char check just documents intent.)
- **Dr.Syed innate passive — 2% LIFESTEAL.** Syed (class `soldier`) heals **2% of all damage HE deals to enemies** (originally 5%), capped at `maxHp`, always on (no key, no cooldown). Implemented as a gated helper `soldierLifesteal(dmg)` (`const SOLDIER_LIFESTEAL = 0.02`, defined just above `explode()`) that no-ops unless `player.char === 'soldier'` and `player.hp > 0` (never revives). It is called at **every site where Syed's own attack subtracts enemy HP**: the player-bullet collision (pistol + powerup weapons), `fireKatana` (blade), `tickFlameburst` (NAPALM), and `explode()` (BARRAGE shells / rocket blasts). **Ally damage is intentionally excluded** — drone/bomber bullets share `owner:'player'`, so they're now tagged `fromAlly:true` (new `createBullet` field + the bomber's raw-bullet literal); the bullet-collision lifesteal is gated on `!b.fromAlly`, and `explode()` gained a trailing `fromPlayer` arg so only player-initiated blasts heal (collision passes `!b.fromAlly`; the end-of-fuse grenade detonation passes `b.owner==='player' && !b.fromAlly`; the `blast` skill passes `true`; enemy explosions pass nothing). Because `explode()`/the melee loops call `soldierLifesteal` **per enemy hit**, the total heal stays exactly 2% of total damage dealt. Healing makes `player.hp` fractional — fine, the HP HUD is a bar (`drawHUD`), not pips. Surfaced on the character-select card as a green `PASSIVE: 2% LIFESTEAL` row below Syed's 5 skills, and in his `CHARACTERS.soldier.desc`. Balance lever: the blade's high DPS × 2% is decent sustain but bounded by the short `energy` pool; the pistol's 2% is negligible.
- **Character display names → `Dr.Syed` / `Xu Yihui` / `Benjamin Wu`.** Char2/char3 dropped from all-caps (`XU YIHUI`/`BENJAMIN WU`) to title case; char1 is `Dr.Syed`. Pure `CHARACTERS.<key>.name` changes — the class keys are still `soldier`/`scout`/`tank`, so all class logic is unaffected. (Older prose below that says "Syed" refers to `Dr.Syed`.)
- **Escape quits to the main menu.** The keydown listener handles `Escape` (leading edge) from any state except `MENU`, setting `state = STATE.MENU; stateTime = 0; paused = false;` — leaving the current run/setup screen for the "initial interface". Added a `MENU / ESC` entry to the in-game `drawHowTo` control row (spacing tightened `i*118 → i*93` to fit 5 columns) and a README controls row. Escape is deliberately **not** in `GAMEPLAY_KEYS` (no `preventDefault`, so browser fullscreen-exit still works). See the *Quit to menu (Escape)* section in systems.
- **Scout laser now has a `power` resource (+ `battery` pickup); Syed energy regen doubled.** Three coupled tweaks: (1) **Syed `energy` self-regen 0.1 → 0.2/s** (2× faster recovery; the regen line in `updatePlaying` now uses `0.2` for `maxEnergy`, still `0.1` for `maxFuel`). (2) **Xu Yihui (Scout) gained a `power`/`maxPower` pool of 20** (Scout-only, set in `createPlayer`) that the laser RMB now drains **1 per volley** — the RMB gate became `... && player.laserCd <= 0 && player.power >= 1`, decrementing `power` after `fireLaserBeams()`. Power **self-regens 0.1/s** (same rate as Tank fuel, per request). HUD: a cyan **POWER** bar in `drawHUD` (mirrors FUEL/ENERGY; only one of `maxFuel`/`maxEnergy`/`maxPower` is >0 so they share the slot) + a `POWER: 20 (RMB)` row on the Scout character card. (3) New **`battery`** pickup (sprite `p_battery`, cyan; `applyPickup` +5 power; registered in `drawPickupEntity` sprMap/glowColors) — the Scout's class resource, added to the Scout/default drop pool at **0.12 (medium frequency)**, which now mirrors the Soldier pool (battery↔beverage) and still sums to 1.0 (validator C5 green). The three drop pools therefore each carry their owner's resource: Tank→fuel, Soldier→beverage, Scout→battery.
- **Added dependency-free validation tooling (`tools/validate.py`) + CI.** First test/lint tooling in the repo. Pure Python 3 stdlib (Python is installed; Node is **not**, which is why a JS test harness wasn't used — and the single-file/no-deps design makes one a poor fit anyway). It is a *static invariant linter*, not a runtime test: brace-balance smoke-check + the numeric invariants that have regressed before (every `mix` sums to 1.0, all 3 drop pools sum to 1.0) plus LEVELS-count/boss-tiers/skill-wiring/GAMEPLAY_KEYS coverage. Verified green on current `index.html` and confirmed (negative test) to FAIL on a broken mix + broken pool. `tools/validate.bat` is a Windows wrapper; `.github/workflows/validate.yml` runs it on push/PR to `main` (signal only — does not gate Pages deploy). See the *Validation* section above. Run it after editing `LEVELS`/drop pools/skills/`GAMEPLAY_KEYS`.
- **Scout RMB → three straight-line HITSCAN laser beams + overall Scout buff.** The Scout's old RMB (a fan of three *travelling, piercing* blue laser bolts) was replaced by `fireLaserBeams()`: three **instant straight-line beams** fanned around the aim that damage *every* enemy on each beam's line **simultaneously** (point-to-segment distance test, `dmg 3 × damageMult`, `LASER_BEAM_HALF 4` thickness). **Scope unchanged**: `LASER_BEAM_LEN 147` (= the old bolt's `speed 420 × life 0.35`) and `±LASER_BEAM_SPREAD 0.18` rad match the old burst's reach/spread exactly. Cooldown tightened `0.3 → 0.22 s`. Rendered as three fading lines via a new `{beam:true, x, y, angle, len}` particle (drawn as a translucent wide glow + bright thin core in the particle loop, handled *before* the `p.ring` branch). The old `SPR.bullet_laser_blue` sprite is now orphaned. **Overall Scout buff in the same pass**: `hp 7→9`, `speed 135→148`, `damageMult 1.1→1.25`, mobility cooldowns `blink 7→5` / `dash 5→3.5`, and the SMG LMB nudged up (`dmg 0.7→0.85`, `speed 340→360`, `cd 0.07→0.06`). Desc updated to `CYBER MECH · 3× LASER BEAM (RMB) · BLINK+DASH`. See the *Right-mouse secondaries* section.
- **All three player sprites redrawn (theme overhaul).** `player_soldier_a/_b` (Syed) → a 21st-century **rainforest warrior**: camo bandana/fatigues, an AK47 across the chest, a dagger at the waist (palette: camo greens 1/2, tan 3, skin 4, gunmetal 5, wood/handle 6, blade 7). `player_scout_a/_b` (Xu Yihui) → a **blue cyberpunk mech**: blue shell 1/2, cyan visor+core 4, navy joints 3, gunmetal pods 5, **left bullet-launcher muzzle 6 (orange), right laser-launcher muzzle 7 (cyan)**. `player_tank_a/_b` (Benjamin Wu) → a **U.S.-Army flamethrower soldier**: dark uniform 1/2, skin 4, dark rifle across chest 5, back-mounted flamethrower tanks (orange 6 + red pilot 7), dark boots 3. Sprite keys are unchanged (`player_<key>_a/_b`), so `playerSprites()` and the character cards pick them up automatically. Descs updated (Syed `SAMURAI·KATANA` → `RAINFOREST WARRIOR·BLADE`, Xu Yihui `ASSASSIN` → `CYBER MECH`). The melee function/consts stay named `fireKatana`/`KATANA_*` (legacy) even though the flavor is now a jungle-warrior blade.
- **Katana scope cut + name shuffle.** Syed's katana arc was reduced to **3/4** of its previous coverage — `KATANA_HALF 1.2 → 0.9` rad (~137° → ~103°, still obtuse; since the swept sector area is linear in the half-angle at fixed `KATANA_RANGE`, this is exactly a 3/4 scope cut). Names reshuffled: char2 (`scout`) is now **Xu Yihui** and char3 (`tank`) reverted to **Benjamin Wu** (display names only; keys unchanged). The older bullets below predate these tweaks.
- **Character renames + Syed's samurai-katana pass.** The 1st char (class key `soldier`) is now **Syed**, the 3rd (key `tank`) is **Benjamin Wu** (briefly Xu Yihui mid-session — see the bullet above) — display-name only; all class logic still keys off `soldier`/`tank`. Syed's sprites (`player_soldier_a/_b`) were redrawn as a **samurai** (steel kabuto + gold crest, crimson armor, dark hakama, long silver katana). His RMB is now a **katana slash** (`fireKatana`, renamed from `fireKnife`): VERY-high `dps 40`, swept over a wide **obtuse** arc (`KATANA_RANGE 32`, `KATANA_HALF 1.2` rad ⇒ ~137°). The obtuse arc is **drawn in-game** as a translucent steel sector in `drawPlayer` (shares the `KATANA_RANGE`/`KATANA_HALF` consts). Both Syed `energy` and Benjamin Wu `fuel` now **self-regen 0.1/s** (added in `updatePlaying`), and the `beverage`/`fuel` drop weights were cut 0.20 → **0.12** (high-medium) to compensate (all three drop pools still sum to 1.0).
- **Syed's RMB energy system** (introduced when the grenade launcher was replaced): drained from a `player.energy`/`maxEnergy` pool (6 = ~6 s, Soldier-only) while RMB held, modeled on Tank's `fuel`/flamethrower. Refilled by the **`beverage`** pickup (energy-drink sprite `p_beverage`, green; `applyPickup` +1 energy; Soldier-only drop via a third branch in `killEnemy`'s drop pools). HUD: a **label-only ENERGY bar** in `drawHUD` (mirrors the FUEL bar; bar fill only, no number) plus an `ENERGY: 6 (RMB)` row on the character card. Energy is float-precise (drained by `dt`). `grenadeCd` field/decay removed; the `grenade` `triggerSkill` handler is now orphaned (its bullet shape still mirrored inline by `barrage`).
- **Soldier & Scout reworked into distinct, competitive classes** (Benjamin Wu / Tank was already the benchmark and is unchanged). Goal: make all three roughly power-equal via *different* vectors. **Soldier = Demolitionist** (`hp 5→10`, AoE-control vector): keeps the pistol LMB but gains a **grenade-launcher RMB** (reuses the `grenade` handler on a 0.7 s `grenadeCd`), C = `flameburst` relabeled **NAPALM** (3 s fire ring), V = new **`barrage`** handler (fan of 5 staggered grenade-shells, `3 × damageMult` each, 24 s cd). **Scout = Mobile assassin** (`hp 3→7`, `speed 130→135`, `damageMult 1.0→1.1`, mobility + ranged-pierce vector): LMB changed from the slow artillery shell to a **fast light SMG** (`dmg 0.7×`, `cd 0.07`, `speed 340`), **3-line piercing blue-laser RMB** (discrete burst of 3 bolts, `pierce:true`, `SPR.bullet_laser_blue`, `2×` each, `speed 420 / life 0.35`, ±0.18 rad spread, 0.3 s `laserCd`), C = `blink` (teleport to cursor, 7 s cd), V = `dash` (directional dodge, 5 s cd) — a glass cannon kept alive by mobility/i-frames. New player fields `grenadeCd`/`laserCd`; new `skillCdMax` entries `dash:5`, `barrage:24`, `blink` bumped to 7; `skillColor` gained `barrage`; `drawPlayer` gained Soldier/Scout RMB reticle branches. Drop pools were intentionally **left unchanged**. (Several follow-ups since: HP Soldier 7→10 / Scout 4→7; Scout RMB pellet-burst → 3-line piercing blue laser; **Soldier's grenade-launcher RMB was replaced by the energy-limited knife slash** described in the next bullet — `grenadeCd` removed, the `grenade` handler now orphaned.) See the *Special skills* and *Right-mouse secondaries* sections.
- **Companion now keeps pace with the player** — `updateCompanion` raised `accel 4.5 → 18` and added a velocity cap of `max(playerEffectiveSpeed*1.35, 90)` (tracks the SPEED powerup), and the position clamp moved from the `W/H` viewport to `worldW/worldH`. The old settings made the drone trail far behind on the 2×/3× arenas and pinned it at the screen edge. `updateSwordAlly`'s clamp was changed `W/H → worldW/worldH` for the same reason.
- **Pick-2-of-5 assistant loadout** (supersedes the earlier always-on drone+henchman design) — a new `ASSISTANT_SELECT` screen sits between character-select and the game; the player chooses exactly 2 of `{drone, henchman, nunchaku, bomber, poison}` (`selectedAssistants`). The drone (auto-fire) and henchman (club brute) are now *selectable* rather than always-on. **Three new allies added:** `nunchaku` (HIGH dmg 8, medium reach 30/108°, fast 0.4s, 5 HP), `bomber_ally` (3 HP, lobs VERY-high-dmg 10 / LARGE-radius 48 bombs via the `isGrenade+explosive` raw-bullet pattern), `poison_ally` (5 HP, wide `auraRadius 50` continuous `dps 5` toxic ring). **Ally system was unified in the same pass:** dropped the `companion`/`henchman` singleton globals for a global `allies` array + `isAlly()`; single `damageAlly(a, amount)` (uses per-entity `hitInvuln`/`deathColor`) replaced `damageCompanion`/`damageHenchman`/`damageSwordAlly`; generic `updateMeleeAlly`/`meleeAllyAttack` serve henchman+nunchaku; collisions/prune-cap/`startLevel` filter all use `isAlly`; `spawnSelectedAssistants` (run start) + `refreshAssistants` (per level, keep survivors / recreate dead) manage the loadout. Screens: `drawAssistantSelect`/`handleAssistantSelect` with `assistCardRect`/`assistStartRect`. Sprites `nunchaku_a/_b`, `bomber_a/_b`, `poison_a/_b`. Note `'bomber_ally'` ≠ enemy boss `'bomber'`.
- **40 levels in 8 boss tiers** (was 30 in 6) — five levels per tier, each tier locked to one boss AI (`bruiser` → `sniper` → `splitter` → `summoner` → `overlord` → `nemesis` → `reaper` → `phantom`). The last two tiers (L31-L35 `reaper`, L36-L40 `phantom`) revived the previously-orphaned `updateReaper`/`updatePhantom` AIs. Within a tier the boss AI is identical but each level keeps a unique `bossName` (BRUISER/RAMPAGER/JUGGERNAUT/COLOSSUS/BEHEMOTH for tier 1, etc.); `spawnBoss`'s per-level HP/speed multiplier handles the difficulty gap inside a tier. Victory screen reads "All N bosses fell" using `LEVELS.length` (no hardcoded number).
- **L16-L20 endgame curve** — totals 66→92, rates 0.36→0.28, mixes shed grunt entirely and lean on tank / shooter / charger / exploder. L20 mix has no runners, just the heavies.
- **L21-L40 push the curve further** — totals climb 100→450 and rate tightens 0.27→0.11. L25 onward is also a 3× world (see Coordinate system), so the heavier spawn pressure plays out across a bigger arena. L30 ANNIHILATOR is the toughest `nemesis`; the overall final boss is **L40 APOCALYPSE** (a `phantom`).
- **Level-select grid is 8×5** (was 6×5) — `levelBoxRect` uses `cols=8, rows=5, bw=26, bh=15, gap=2` to fit 40 boxes; the 8-wide row spans 222px, centered, starting at `ys=124`, leaving room for the HIGH SCORE line at `y=215`. The CLEAR/— second-line text was dropped when boxes shrank from `bh=18` to `bh=15`; the box's green-vs-blue color is now the sole cleared indicator. If you add more levels, this layout will need another reshape.
- **Companion stats tuned up** — HP 6, fire rate 0.25 s, bullet dmg 3 / speed 260 / life 1.5, detection radius 140 units, post-hit invuln 0.85 s. (Was HP 3 / 0.32 s / dmg 1 / speed 220 / radius 110 / invuln 0.7 originally.)
- **Sword ally stats** — HP 4 (was 3), `swingDmg: 5` (was 3), `attackArc` 120°, `attackRange` 24, `attackRate` 0.55 s, 30 s spawn invuln 0.3 s.
- **Tank overall buff pass** — Tank stats raised significantly so it's competitive with Soldier/Scout: `hp: 8→12`, `speed: 80→95`, `damageMult: 1.0→1.2`, `startShield: 3→4`, `shieldMax: 3→5` (tank only), `maxFuel: 8→12`. Flamethrower: `range: 180→210`, `halfAngle: 0.6→0.7` (~40°), `dps: 5→7`. Flamethrower DPS still scales with `damageMult` and the `damageTime` powerup. Tank's `desc` text in `CHARACTERS` updated to `'HEAVY · +20% DAMAGE · FLAMETHROWER (RMB)'`.
- **Tank now has a dedicated default weapon (heavy slug)** — `fireWeapon`'s class-default branch added a `player.char === 'tank'` case BEFORE the soldier-pistol fallthrough. Tank slug: `dmg: 2`, `radius: 3`, `speed: 300`, `life: 1.6`. Same `fireRate` as the pistol (so cadence is unchanged), but each shot does 2× base damage (≈2.4 after `damageMult: 1.2`). The old comment "Tank's left-click is the same as Soldier's pistol" is no longer true — update it if you reshuffle this function.
- **Tank drop pool** — fuel and armor get real slices; both pools sum to 1.0. The fuel-never-drops bug from the prior implementation is fixed.
- **Armor pickup (`armor`)** — "extra protective case". Raises `shieldMax` to 5 (cap was 3), refills shield, grants 1.5 s invuln on grab.
- **Magnet pickup** — was 0.04 weight (≈0.9% per kill). Bumped to 0.06-0.08 (≈1.3-1.8% per kill).
- **Screen shake disabled** — `draw()` no longer applies the translate. Per user preference; combat code still assigns `shakeTime`/`shakeAmt`, so this is a one-line revert.
- **Fuel HUD shows label only** — the numeric fuel value (`'FUEL X.X'`) was replaced with just `'FUEL'`; the bar still shows the ratio visually.
- **Tank's B-key flame burst was replaced by a V-key `vsummon`** — the Tank's sword-summon slot moved from `b` to `v`. `vsummon` (label `BLADE+`, 25 s cooldown) summons the standard sword knight with `attackRate /= 1.5` (faster swings). The old `flameburst` handler, the `player.flameburstTime` timer, and `tickFlameburst(dt)` are now **orphaned** — still present and decayed but no key triggers them. (The **B key later returned** as the universal `blast` skill — unrelated to flameburst; see the *Special skills* section.)
- **Skill set reworked to X (sprint) / C (class) / F (heal) / B (blast) / V (Tank vsummon)** — X stopped summoning the sword knight and became the +30% sprint buff (`playerSpeedMult()` stacks it with the SPEED powerup); F (heal +1 HP, no-waste at full) and B (small-radius `blast` via `explode()`) were added as universal 20 s skills; `summon` is now orphaned and the sword knight lives only on the Tank's V. `GAMEPLAY_KEYS` gained `KeyF` and `KeyB`; the character card became data-driven and grew to 172 px to fit five skill rows (this also fixed a pre-existing DMG/SHIELD/FUEL overlap on the Tank card).
- **Display-name shuffle** (keys never change, so class logic is unaffected): char3 `tank` = **"BENJAMIN WU"** (was briefly renamed to XU YIHUI then reverted), char2 `scout` = **"XU YIHUI"** (was "SCOUT"), char1 `soldier` = **"SYED"** (was "SOLDIER"). All three are pure `CHARACTERS[key].name` display changes.
- **Space pause/resume** — see the *Pause (Space)* section. Global `paused` flag; `update()` skips `updatePlaying` while set; `drawPause()` overlays the banner; resume via Space or any click.
- **Tank fuel drop weight bumped 0.13 → 0.20** — fuel pickups appear ~50% more often for Tank so the flamethrower stays viable on long levels. The other 14 slots in the Tank pool (health 0.10, slowmo 0.03, score2x 0.02, rocket 0.04, magnet 0.05, …) were shaved to keep the weights summed to exactly 1.0. The non-Tank pool was untouched.
- **Boss HP/speed scale per level** — `spawnBoss` multiplies the base per-kind stats by `1 + levelIdx*0.07` (HP) and `1 + levelIdx*0.015` (speed). At L1 (idx 0) the multiplier is 1.0 so bruiser is unchanged; by L40 (idx 39) it is ~3.73× HP / ~1.59× speed. Without this, reusing one AI per 5-level tier would make L26 NEMESIS exactly as tough as L10 — the scaling is what makes each reuse of an AI feel meaningful across all 8 tiers.
